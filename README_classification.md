# Twitter Profile Classification Analysis

This component of CSCI446/946 Assignment 2 classifies Twitter profiles as **human** or **non-human** and identifies profiles whose recorded labels may require review.

The original `gender` labels are converted into a binary target:

- `male` and `female` -> `human` (`is_human = 1`)
- `brand` -> `non-human` (`is_human = 0`)
- `unknown` -> no supervised target; retained for prediction only

Classification disagreement is treated as evidence for review, not proof that an existing label is incorrect. Final amendment recommendations should combine classification with text processing, clustering, association rules and manual inspection.

## Inputs

`04_classification.py` expects four files generated by `02_preprocess.py`.

### `twitter_train.csv`

Used to fit candidate models during hyperparameter selection.

### `twitter_validation.csv`

Used to select model hyperparameters and decision thresholds. The threshold for each model is selected to maximise validation macro F1 rather than automatically using 0.5.

### `twitter_test.csv`

Held out during training and tuning. Used once for final model comparison and error analysis.

### `twitter_full.csv`

Contains all processed profiles, including low-confidence, conflicting and unknown records. It is used to generate out-of-fold predictions, mislabelling candidates and suggested labels for unknown profiles.

## Features

The script uses 38 engineered metadata features prepared by `02_preprocess.py`:

- Account activity: favourite count, tweet count, tweets per day and favourites per day.
- Account characteristics: account age, name length indicators and profile completeness.
- Tweet structure: text length, URLs, mentions, hashtags and emoji presence.
- Description structure: description length, missing description and URL presence.
- Profile settings: default image, default/custom link and sidebar colours.
- Location information: coordinates, missing location, missing timezone and encoded common timezones.
- Colour information: red, green and blue channels extracted from link and sidebar colours.

Highly skewed count variables are log-transformed by `02_preprocess.py`. Numeric variables are standardised using parameters learned from the training split only.

The following columns are never used as predictive features because they are identifiers, labels or potential sources of target leakage:

```text
_unit_id
name
gender
gender:confidence
label_conflict
is_human
```

Raw text is excluded from this metadata classification analysis. Text is analysed separately by the text-processing workstream.

## Reliable labels and candidate records

By default, supervised model development uses only records satisfying:

```text
gender:confidence >= 1.0
label_conflict == 0
```

This prevents the classifiers from learning directly from the low-confidence and conflicting labels that the project is attempting to investigate.

| Split | Original rows | Reliable rows used | Uncertain/conflicting rows held out |
|---|---:|---:|---:|
| Train | 10,606 | 7,826 | 2,780 |
| Validation | 3,536 | 2,600 | 936 |
| Test | 3,536 | 2,657 | 879 |

The confidence threshold can be changed from the command line, but `1.0` is recommended for the main experiment.

## Models

The analysis applies classification algorithms covered in the subject materials.

### Dummy Classifier

Predicts the majority class and establishes a minimum baseline. Its high apparent accuracy demonstrates why accuracy alone is unsuitable for the imbalanced dataset.

### Decision Tree

Provides interpretable decision rules and feature importance. It is especially useful for explaining which profile properties separate human and non-human accounts. The analysis investigates split criterion, maximum depth, minimum samples per leaf and class weighting.

### K-Nearest Neighbours

Classifies a profile according to similar profiles in the engineered feature space. It provides a conceptually independent, local-similarity view. The analysis investigates the number of neighbours, uniform versus distance weighting, and Manhattan versus Euclidean distance.

### Gaussian Naive Bayes

Provides a fast probabilistic model for comparison. Its conditional-independence assumption is imperfect because several activity and colour features are correlated. Its probability estimates are therefore interpreted cautiously.

### Multilayer Perceptron

Models nonlinear interactions among activity, profile completeness, URL usage, colours and other metadata. Early stopping limits overfitting. The analysis investigates hidden-layer structure, regularisation strength and learning rate.

## Classification workflow

1. Load and validate the four processed CSV files.
2. Infer the feature schema from the training file.
3. Reject identifier, target and leakage columns.
4. Convert features to numeric values and replace infinite values with missing values.
5. Apply median imputation inside each model pipeline.
6. Standardise features for KNN and MLP.
7. Retain only fully confident, non-conflicting labels for supervised learning.
8. Fit all hyperparameter configurations on the training split.
9. Select parameters and decision thresholds using validation macro F1.
10. Refit the selected configuration on training plus validation data.
11. Evaluate each model once on the held-out test set.
12. Produce out-of-fold predictions for reliable labelled profiles.
13. Predict low-confidence, conflicting and unknown profiles using models that did not train on those records.
14. Rank potentially mislabelled profiles using agreement across models.

## Evaluation metrics

The dataset is imbalanced, with human profiles forming the majority class. The analysis therefore reports multiple complementary metrics.

| Metric | Purpose |
|---|---|
| Accuracy | Overall proportion of correct predictions; interpreted relative to the Dummy baseline |
| Balanced accuracy | Mean recall across human and non-human classes |
| Macro F1 | Primary metric; gives equal weight to both classes |
| Weighted F1 | Overall F1 adjusted for class frequency |
| Class precision | Reliability of predicted human and non-human labels |
| Class recall | Proportion of each recorded class successfully identified |
| Matthews correlation coefficient | Balanced summary of binary classification quality |
| ROC-AUC | Ability to rank human above non-human profiles across thresholds |
| Non-human average precision | Precision-recall performance for the minority non-human class |
| Brier score | Accuracy of predicted probabilities; lower is better |
| Log loss | Penalises incorrect and overconfident probabilities; lower is better |

Confusion matrices, ROC curves, precision-recall curves and calibration plots support visual evaluation.

## Potentially mislabelled profiles

Reliable labelled profiles receive out-of-fold predictions so that a profile is not judged by a model trained directly on that same profile. Low-confidence, conflicting and unknown records are predicted as held-out records.

A labelled profile enters the broad review pool when at least three of the four trained models predict the class opposite to its recorded label. A strong candidate requires at least three models to contradict the recorded label with predicted-class confidence of at least `0.80`.

| Candidate category | Profiles |
|---|---:|
| Broad review candidates | 2,808 |
| Strong candidates | 1,047 |
| Recorded human profiles flagged | 1,019 |
| Recorded non-human profiles flagged | 1,789 |
| All four models contradict recorded label | 1,672 |
| Three models contradict recorded label | 1,136 |

These records are not confirmed errors. They are candidates for cross-checking against text, clustering, association-rule and manual evidence.

For a stricter final-review subset, the project can require Decision Tree, KNN and MLP to all contradict the recorded label with probability at least `0.80`. This produces 707 high-priority candidates and avoids relying on the poorly calibrated Naive Bayes probabilities.

## Why this classification analysis matters

Classification is not used only to maximise predictive accuracy.

1. **It establishes a reproducible baseline.** The Dummy model shows whether trained models learn meaningful structure beyond class prevalence.
2. **It compares multiple assumptions.** Rule-based, neighbourhood-based, probabilistic and nonlinear approaches are evaluated consistently.
3. **It identifies systematic factors.** Decision Tree importance connects predictions to activity, URL usage, image defaults and profile completeness.
4. **It avoids in-sample label checking.** Out-of-fold predictions reduce the risk of flagging profiles because a model memorised them.
5. **It prioritises manual review.** Agreement and confidence transform thousands of profiles into ranked review tiers.
6. **It supports multiple-view validation.** Candidates can be combined with text, clustering and association rules before amendment.

The output is therefore a decision-support mechanism for identifying potentially mislabelled profiles, not an automatic relabelling system.

## Interpretation limitations

- Crowd annotations are not independently verified ground truth.
- Each account contains only one sampled tweet.
- Profile behaviour and ownership may change over time.
- Metadata-only models do not directly understand tweet or description meaning.
- Brand accounts are heterogeneous and can behave like personal accounts.
- Colour and timezone features may reflect platform defaults rather than identity.
- Model disagreement may indicate an unusual but correctly labelled account rather than an annotation error.

Any final label change should therefore require supporting evidence from more than one analytical view.
